Add a live send-test for the order confirmation email

order-email-send-test.cjs only covered the four lifecycle emails, so there
was no way to put a confirmation in a real inbox. That is the one template
whose whole purpose is the number at the top, and the number is exactly what
you cannot check from a headless render.

Four fixtures, one per payment shape the template can take, with a --dry-run
and --admin flag. Two decisions worth stating:

The order id is stamped per run. The idempotency key is
`order-confirmation-${orderId}`, so a fixed test id would let the provider's
de-duplication swallow the second and every later send, and the script would
report success while delivering nothing. A per-run id cannot collide with a
real order.

The admin alert is suppressed by default, because ADMIN_EMAILS is the real
inbox and a test run should not page it. Passing --admin includes it.

Firestore is stubbed with a no-op set(), so a test run cannot create or mutate
an order document. The transport is not stubbed — real template, real sender,
real provider.

Also fixes a break in the existing status send-test, which was already dead
on arrival since the chrome refactor: order-email.ts imports the confirmation
module unconditionally, and neither "./emailChrome" nor the confirmation
alias was supplied, so it exited with MODULE_NOT_FOUND on the first line of
work. The refactor's own suite never covered it because order-email-smoke.cjs
already supplied both, which is why the omission went unnoticed.
